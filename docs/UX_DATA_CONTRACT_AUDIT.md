### History/price (all five: available, presentation/range-contract gap)

Alpaca → daily provider/file cache → website memory cache → bars/detail APIs → hidden StockPage details with last20-point SVG/table. Bars do **not** depend on the event DB. `alpaca_market.py:143–209` requests IEX, `adjustment=raw`, page size10,000 and follows continuation tokens with repeat-token protection. Website caches five minutes, defaults to ≥400 calendar days, clamps end to today, excludes today's bars and returns only the latest `limit` rows (API1–5000). There is no advertised maximum history span or completeness indicator; an arbitrarily early start can cause excessive paging. Auth/permission/rate failures are sanitized but conflated into provider_error; empty has deliberately uncertain reason.

**1D means a one-day viewport, not “daily timeframe.”** Current provider supports daily samples only: no honest intraday 1D chart. Disable/label intraday unavailable, or explicitly label a single completed daily observation; never synthesize minute points. Daily 1M/3M/6M/YTD/1Y/5Y views can request actual date ranges; 5Y is proven here only for AAPL. Raw split/dividend discontinuities and IEX-only volumes must be visible. A daily bar timestamp is a session label, not the exact closing-trade time. Historical windows must not replace the independently fetched latest available header price.

## 3. Proposed frozen, existing-compatible API contracts

These are implementation contracts for UX3/4/6, **not claims that fields already exist**. Keep existing endpoints/arrays and scalar aliases; add optional metadata, never replace lists with envelopes. All unknown numbers/times/names remain null; machine statuses distinguish unsupported/unavailable/not_refreshed/empty/provider_error/stale/partial/available. Errors must not echo request credentials.

1. **Bars:** preserve `GET /api/v1/market/bars/{symbol}?timeframe=1Day&start=YYYY-MM-DD&end=YYYY-MM-DD&limit=1..5000` and `bars:[{t,o,h,l,c,v}]`, status/reason/mode/source/source_url/retrieved_at/market_timestamp. Add `requested_start`, `requested_end`, `effective_end`, `available_start`, `available_end`, `returned_count`, `truncated`, `coverage_complete` (nullable unless established), `feed:"iex"`, `adjustment:"raw"`, `timestamp_basis:"daily_session_label"`, `supported_timeframes:["1Day"]`. Available bounds describe **this response**, not earliest provider history. Enforce proposed maximum10-calendar-year span and return400 rather than silently clipping larger requests; disclose policy. `limit` is a tail cap, not provider page size. Preserve no-current-session rule and independently request latest price. UTC timestamp→session date conversion must not shift dates using browser locale.
2. **Current available price:** preserve top-level `price/change/change_pct/volume` aliases and `price_data` fields; define them as last completed daily close and prior available session comparison. Add `price_data.session_date`, `feed`, `adjustment`, `timestamp_basis`, `is_live:false`. Keep market_timestamp versus retrieved_at distinct. No automatic “current/live” badge; stale close remains dated/stale rather than zero. A future genuine quote would require a new explicit price_kind/source/latency contract.
3. **Identity:** preserve `name/exchange`; add `identity:{symbol,cik,name,exchange,sector:null,industry:{scheme:"SEC_SIC",code,label},description:null,status,coverage,source,source_url,retrieved_at,verified_as_of,verification_scope:"official_snapshot",fields:{...}}`. Per-field evidence carries source_url/retrieved_at/evidence_span/source_effective_at (nullable). `verified_as_of` means snapshot observation, not historical validity or continuous current verification; never populate with response time alone. Invalid/missing mapping must not claim symbol verified merely because a bar exists. Snapshot/revision evidence must survive later updates.
4. **Next earnings:** add nullable `next_earnings` plus explicit `earnings_coverage` to stock detail; retain `/earnings` as the existing history array. Use existing MarketEvent `event_type=earnings,status=scheduled,scheduled_at=null` unless exact release clock+zone is sourced. Metadata: `event_date`, `session:bmo|amc|dmc|unknown`, `scheduled_time_precision:date|session|exact`, `event_timezone` (nullable if unsupported), `event_kind:results_release|earnings_call`, `verification_status`, `retrieved_at`, `evidence_span`, `source_document_id`. Existing `metadata.time` stays a compatible session alias. Include only official explicitly announced future **results_release** events in next_earnings; source-evidenced calls remain separate events. Calendar export preserves date/session semantics; no midnight/BMO09:00/AMC16:00 inference, no webcast→release substitution, no invented consensus.
5. **Transactions:** retain insider event arrays and `metadata.ownership` fields above. Table rows derive identity `${event_id}:${transaction.index}` within accession, with accession/source URL/retrieval and owners[] attached once per row; no allocation by owner. Keep decimal strings/null, raw codes, parser classification and evidence footnotes. `ten_b5_one` is nullable filing-level disclosed checkbox, not a per-row inference. Optional row-level plan assertion requires cited footnote evidence. Filter purchases/sales by P/S; “all transactions” includes other classifications. Values are shares×reported price only, not independent cash-flow evidence.
6. **Dedup/timeline:** accession + event_type remains storage identity; transaction index identifies a row within that source version. Group same-accession SEC filing and insider/leadership representations in UI, but retain each event/evidence link. Do not dedup distinct same-day transactions by owner/date/value. `/A` is a distinct amendment with `amends_accession=null` unless a link is evidenced; no heuristic replacement. Cross IR/exhibit copies may be grouped by proven canonical URL/hash/document relationship, never title similarity alone. Preserve revisions and original timestamps/provenance; no mass deletion/rewrite.
